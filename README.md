# 国标麻将对战机器人

一个C++17课程项目。程序维护自己的手牌、副露和未见牌数量，枚举候选目标牌型，以启发式估价选择目标，再决定弃牌或吃碰杠胡。搜索采用深度优先枚举、条件筛选和CPU时间截断；没有实现MCTS或对手策略网络。

## 工程结构

```text
main.cpp                                      牌面表示、协议循环、搜索和动作决策
MahjongGB/                                    国标算番接口适配
ChineseOfficialMahjongHelper/Classes/
  mahjong-algorithm/                           第三方算番、向听数与牌型基础代码
CMakeLists.txt                                C++17构建入口
SOURCE-MANIFEST.json                          历史源版本与提取文件摘要
NOTICE.md                                    来源与署名说明
```

main.cpp直接包含MahjongGB/MahjongGB.h；该头文件进一步包含若干实现文件。因此当前入口只编译main.cpp，不要再次把被包含的.cpp独立加入同一个链接目标，否则可能产生重复定义。

## 构建

需要支持bits/stdc++.h的GCC环境。CMake方式还需要CMake3.28或以上。

```sh
g++ -std=c++17 -O2 main.cpp -o mahjong
# 或
cmake -S . -B build
cmake --build build
```

Windows可使用自行安装的MinGW-w64；Linux可使用GCC。当前源码使用GCC优化pragma和bits/stdc++.h，没有完成MSVC可移植性整理。

## 运行逻辑

输入使用源码中的简化文本交互，进程跨回合保留状态，并以`>>>BOTZONE_REQUEST_KEEP_RUNNING<<<`输出继续运行标记。这不是默认JSON请求封装。使用平台时应选择匹配的交互模式，不能把任意JSON直接送进当前main。

1. init读取玩家编号、圈风和初始手牌，初始化未见牌计数与算番库。
2. 主循环根据摸牌、出牌、吃、碰、杠等事件更新状态。
3. JudgeHu调用第三方国标算番器，并按当前程序的8番门槛决定是否声明胡牌。
4. FindBest与dfs构造目标牌型，getss综合合法番数、目标缺牌及未见牌数量计算启发式分数。
5. ChuPai围绕目标牌型选出可弃牌；其他处理函数决定吃碰杠及相应状态变化。

`leave`表示从自身观察中尚未确定位置的牌数，不代表程序知道其他玩家的真实手牌。目标评分是手工启发式，不是校准后的胡牌概率。0.95秒检查使用clock的进程CPU时间，也不等于所有平台上的墙钟硬超时保证。
